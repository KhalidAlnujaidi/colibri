Colibrì — prompt → token

How one keystroke becomes a streamed token: an ASCII architecture walkthrough of the repo, rendered as HTML.

Python · orchestration C · inference engine SSD → RAM → VRAM
One-line thesis: a Python orchestration layer (c/coli, c/openai_server.py) renders prompts and speaks HTTP/frames; a pure-C inference engine (one .c file per model family) does tokenizing, forward passes, sampling, and streams bytes back — while treating SSD → RAM → VRAM as a single memory hierarchy.

Basis: one prototype, many thin implementations. All families reuse tok.h/sample.h/tier.h (header-only libs), so the prompt→token pipeline is written once per repo, not once per model.

Basis: the process boundary is the API boundary. Engines never parse JSON — they receive byte-counted lines and emit byte-counted frames (docs/serve_protocol.md), so any front-end can replace any other.

2Inside one turn prefill vs decode

 prompt ids:  [ciao , !]             n_new = 3
              │
              ▼
  ┌──────────────────── PREFILL  (S = prompt length) ────────────────────┐
  │  embed(ids) ▸ [ layer ] ▸ [ layer ] ▸ … ▸ lm_head                    │
  │  fills the KV cache for every prompt position at once                │
  │  costs O(S · layers) once, hides first-token latency    c/qwen36.c:2900
  └────────────────────────────────┬─────────────────────────────────────┘
                                    │ logits for position p
                                    ▼
        DECIDE ── pick_tok():  temp<=0 → argmax, else top-p sample   c/sample.h:100
                                    │ id = 763
                    ┌───────────────▼────────────────┐
  token 1 = "Ciao" │  stream_token(id) ▸ bytes      │──▶ client (SSE DELTA)
                    └───────────────┬────────────────┘
                                    │ feed last id only (S = 1)
                                    ▼
             ┌──────────────── DECODE  (one token per step) ───────────────┼─
             │  embed(1) ▸ layers_forward ▸ lm_head ▸ pick_tok             │
             │  KV cache grows by 1 position; attention reads it back       │
             │  repeat until: stop token | max_tokens | ESC                │
             └───────────────────────────────────────────────────────────────┘

  compare:   # two hardware personalities in one loop
  prompt  ▲██████████████████░░  (wide matrix multiplies → compute-bound)
  decode  ░ ▓ ░ ▓ ░ ▓ ░ ▓ ░ ▓  (skinny spikes → memory-bandwidth-bound)

Basis: prefill is math-bound, decode is bandwidth-bound. Every feature (KV prefix reuse, expert prefetch, batched slots) exists to hide the decode spikes behind I/O.

Basis: only top-k experts are computed per token (~% of a 744B model activates), and only they must live in fast memory — which is why the storage layer is the heart of this repo.

  a 744B model, resident ~9.9 GB ── the trick, in one line:

  .safetensors ──int4/int8 row+scales──▶ mmap ▸ experts streamed per-hit ▸
  top-k only ▸ router never changes semantics
  ("insufficient fast memory may reduce speed; it must not quietly redefine the model")

Basis: a cache with a scheduler — storage/RAM/VRAM admit experts by measured routing heat, with a background pilot turning disk latency into overlapped work.

5Serve wire exchange mux protocol, coli serve

 server                                   engine  (c/colibri.c:9417 run_serve_mux)
   │  ──▶ READY ◀── READY sentinel handshake            │
   │  ◀── HWINFO / TIERS / EMAP ── telemetry           │
   │  ──▶ SUBMIT <id> <slot> <bytes> <max> <t> <p>      │
   │       <bytes of rendered prompt>                   │
   │                                                    ▼
   │                        prefix-match slot KV (truncate-extend reuse)
   │                        PREFILL serially ▸ DECODE continuously batched
   │                        (up to 16 slots, one row per forward)
   │  ◀── DATA <id> <n>  "\xC3\x80… "   token text    │
   │  ◀── DATA <id> <n>  " come stai?"               │
   │      (repeat × N)                                 │
   │      middleware: UTF-8 assert, StopFilter, TOPK, entropy, PERF
   │  ◀── DONE <id> STAT <toks> <tok_s> <hit%> …        │
   ▼ HTTP: SSE `data: {delta}` … `data: [DONE]`

Basis: stateless HTTP turns stay cached because the engine reuses the common KV prefix across SUBMITs — truncate-and-extend.

6The stack, compressed

  your keystroke
      ▶ coli (Python)        — plan, env, launch
        ▶ openai_server.py   — prompt rendering, HTTP, filters
          ▶ serve loop + frame protocol  — slots, batching, telemetry
            ▶ tok.h ▸ step():  embed ▸ layers ▸ lm_head    — the math
              ▶ sample.h ▸ pick_tok()                    — the choice
                ▶ tier/expert_store + backends          — the hardware
      ◀── STREAM: bytes become text, token by token
Python / orchestration engine (C) tier / cache hardware / success path backends / output comments / telemetry

Decides what to ask

c/coli + c/openai_server.py: model resolution, prompt rendering, HTTP, stop filters, tool framing.

Decides what the token is

tok.h → step() → sample.h: the forward pass and the sampler choose each id.

Decides where weights live

tier.h/expert_store.h + SIMD/CUDA/Metal/Vulkan: get the routed experts into fast memory long enough to compute.
