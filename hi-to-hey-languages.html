"hi" → "hey" — the languages in the journey

Exactly two languages run on the live path for this one turn: Python (frontend/gateway) and C (the engine). Everything else is build glue or an optional dashboard.

Python
sends it
C
thinks it
Python
streams it back

1The "hi" → "hey" journey, language by step

   you type "hi"
      │
      ▼
 ┌─────────────────────────────── PYTHON ────────────────────────────────┐
 │ c/coli (CLI)                                                         │
 │   · reads your keystroke, resolves the model, sets env vars          │
 │   · spawns the engine process (C binary)                             │
 │                                                                    │
 │ c/openai_server.py  (in the `coli serve` / `coli chat` path)        │
 │   · render_chat_*():  wraps "hi" with the model's chat template     │
 │     e.g.  "<|user|>\nhi\n<|end|>\n<|assistant|>"                 │
 │   · SUBMIT frame: prompt string + byte count + temp/top-p           │
 └───────────────────────────────┬──────────────────────────────────────┘
                                  │  pipes: SUBMIT <id> <slot> <bytes> <max> <t> <p>
                                  ▼
 ┌──────────────────────────────── C  ─────────────────────────────────┐
 │ THE ENGINE  (c/colibri.c, c/qwen36.c, c/glm53.c …)                 │
 │   · tok.h  (C)      BPE-tokenize "hi"   → id e.g. [11758]        │
 │   · step() (C)      embed → layers → lm_head → logits over vocab │
 │   · sample.h (C)    pick_tok() → next id (e.g. 3189 → "hey")      │
 │   · stream_token()  id → UTF-8 bytes → DATA <id> <n>\n hey\n      │
 └───────────────────────────────┬──────────────────────────────────────┘
                                  │  DATA frame with the decoded text "hey"
                                  ▼
 ┌─────────────────────────────── PYTHON ───────────────────────────────┐
 │ c/openai_server.py                                                  │
 │   · reads the DATA frame, re-assembles UTF-8 bytes                 │
 │   · wraps as SSE  data: {"delta":{"content":"hey"}}                │
 │   · StopFilter checks for stop tokens                              │
 └───────────────────────────────┬──────────────────────────────────────┘
                                  ▼
   you see "hey"

The process boundary between the two languages is the pipe: Python writes framed lines on stdin, C answers with framed lines on stdout.

2Which language runs where

STEP                        LANGUAGE      FILE
────────────────────────────────────────────────────────────
CLI: read "hi", launch       Python        c/coli
Prompt rendering + HTTP/SSE   Python        c/openai_server.py
Tokenize "hi" → ids          C           c/tok.h
Forward pass → logits        C           c/<family>.c  (step / layers_forward / lm_head)
Sample next id ("hey")       C           c/sample.h  (pick_tok)
Decode id → bytes            C           c/tok.h / c/qwen36.c (stream_token)
Wire protocol frames         C → Python   engine stdout → openai_server.py
Stream to client             Python        c/openai_server.py

3What does not run for this turn

 C++ / CUDA / Metal / Vulkan   only when a GPU backend is compiled in —
                                not on a CPU-only build, and never changes
                                the "hi" → "hey" logic.

 Bash / .cmd / .ps1 scripts   build + install glue only (setup.sh, warmup.ps1, …)

 TypeScript / Svelte / HTML   optional web/ dashboard (Brio, Brain) — not needed
                                for a plain text exchange.

4The one-line answer

   Python (frontend / gateway)  →  C (tokenizer + forward + sampler)  →  Python (SSE back to you)
Python — frontend, gateway, HTTP/SSE C — tokenizer, forward pass, sampler C++/CUDA — GPU-only, not on this path Build scripts / web — optional
