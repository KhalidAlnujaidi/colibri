"hi" → "hey": the orchestration layers in C/C++

The three Python stages (CLI launch, prompt render + SUBMIT write, frame read + SSE) rewritten in C and C++. The engine (C) stays as-is — we're only translating the surrounding glue.

C (rewrite)
// fork + exec the engine, wire up pipes
int to_engine[2], from_engine[2];
pipe(to_engine); pipe(from_engine);
pid_t pid = fork();
if (pid == 0) {
    dup2(to_engine[0], STDIN_FILENO);
    dup2(from_engine[1], STDOUT_FILENO);
    execl(GLM, GLM, cap_str, NULL);   // engine = C process
}
// parent: read a line of input, forward it
char *line = NULL; size_t n = 0;
getline(&line, &n, stdin);              // "hi"
write(to_engine[1], line, strlen(line));

C (rewrite)
const char *prompt =
    "<|user|>\nhi\n<|end|>\n<|assistant|>";
int payload_len = (int)strlen(prompt);
char header[128];
snprintf(header, sizeof header,
    "SUBMIT %llu %d %d %d %g %g\n",
    req_id, slot, payload_len,
    max_tokens, temperature, top_p);
write(fd_in, header, strlen(header));  // header + \n
write(fd_in, prompt, payload_len);     // payload, exact bytes
write(fd_in, "\n", 1);

C (rewrite)
// read one line:  "DATA 1 3"
char kind[8]; unsigned long long id;
int n;
if (fscanf(f_out, "%7s %llu %d\n",
           kind, &id, &n) != 3) break;

fread(buf, 1, n, f_out);            // exactly n bytes: "hey"
fgetc(f_out);                        // trailing '\n'

fflush(stdout);                       // → SSE `data: ...`

Why the rewrite is mechanical — but the Python is still there

Good: these three stages are pure glue — byte framing and process wiring — so they translate cleanly to C/C++ (pipe/fork/exec, fscanf/fread). Nothing about the math changes.

Why the real repo keeps them in Python: the render step needs the full chat-template library per family, SSE/HTTP needs a server, tool-call framing and JSON parsing are far less painful in Python, and the gateway is only in the serve path — the engine itself is already pure C. Rewriting this glue would trade ergonomics for no speed (the engine is the bottleneck, not a pipe read).
